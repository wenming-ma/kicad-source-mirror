  1. 核心问题定义

  目标功能：用户选择 N 条网络（如 8 位数据总线），从起点开始布线，鼠标移动时所有
   N 条走线同时跟随，保持固定间距并避开障碍物。

  5.3 MVP 实现范围

  根据用户指定的原则："MVP 聚焦几何（间距和平行），长度/SI 优化留待后续"

  MVP 包含：
  - ✅ 用户选择 N 条网络启动多线布线
  - ✅ 鼠标移动时 N 条线同步跟随
  - ✅ 保持固定间距（来自设计规则）
  - ✅ 基本障碍物避让（Walkaround 模式）
  - ✅ 45°/90° 角度约束
  - ✅ 转角间距维护

  MVP 不包含（后续扩展）：
  - ❌ 长度匹配（Length Tuning）
  - ❌ 信号完整性分析
  - ❌ 差分对耦合
  - ❌ 动态间距调整（B/Shift+B 快捷键）
  - ❌ 自动网络重排序

  6. 伪代码示意

  class MULTI_LINE_PLACER : public PLACEMENT_ALGO {
      // Move() 核心逻辑
      bool Move(const VECTOR2I& aP, ITEM* aEndItem) override {
          // 1. 计算 leader 的新段
          SEGMENT leaderSeg = ComputeSegmentToward(m_lines[m_leaderIdx], aP);
          
          // 2. 为每个 follower 生成偏移段
          for (int i = 0; i < m_lines.size(); i++) {
              if (i == m_leaderIdx) continue;
              VECTOR2I offset = GetPerpendicularOffset(leaderSeg.Direction(),
  m_offsets[i]);
              m_pendingSegs[i] = leaderSeg.Translated(offset);
          }
          m_pendingSegs[m_leaderIdx] = leaderSeg;

          // 3. 碰撞检测
          for (auto& seg : m_pendingSegs) {
              if (CollidesWithObstacles(seg)) {
                  if (m_mode == PUSH_SHOVE) {
                      TryPushObstacles(seg);
                  } else {
                      return ShowBlockage();  // 阻塞
                  }
              }
          }
          
          // 4. 更新预览
          UpdatePreview(m_pendingSegs);
          return true;
      }
  };

  8. 结论

  多线同步布线是一个工程实现问题而非纯学术问题，商业工具通过以下组合实现：

  1. Leader-Follower 策略 - 用户控制主线，其他线按偏移跟随
  2. Push-and-Shove 引擎 - 重用现有 PNS 推挤能力
  3. 增量计算 - 只更新受影响的局部几何
  4. Gateway 匹配 - 在关键点（转角、障碍）同步所有线

  MVP 实现路径：
  1. 创建 MULTI_LINE_PLACER 类，继承 PLACEMENT_ALGO
  2. 参考 DIFF_PAIR_PLACER 扩展到 N 条线
  3. 复用 MULTI_DRAGGER 的 offset 管理逻辑
  4. 先实现 Walkaround 模式，后续添加 Push-Shove
  5. 聚焦几何正确性，长度匹配作为独立后续步骤

  2. 核心工程难点

  难点 1: 多线路径一致性 (Path Consistency)

  问题描述

  当主线（Leader）遇到需要转向的情况时，所有跟随线（Followers）必须在相同的逻辑
  位置转向，但物理坐标需要偏移。关键挑战在于：

  1. 转角位置偏移：内侧线转角点与外侧线转角点坐标不同
  2. 拓扑一致性：所有线必须具有相同数量的段和相同的转向序列
  3. 实时计算：每次鼠标移动都需要重新计算所有线的路径

  问题示例 - 转角处的间距扩张:

                ↑ 间距扩大（违规）
      ┌─────────●━━━━━━━━━━  Line 0 (Leader)
      │         ┆
      │    ┌────●━━━━━━━━━━━  Line 1
      │    │    ┆
      │    │  ┌─●━━━━━━━━━━━━  Line 2 (最内侧)
      │    │  │
      │    │  │
      ●────●──●
     L0   L1  L2

  转角处，L0 和 L2 之间的实际距离 > 设定间距

  解决方案

  方案 A: 交错转角法 (Staggered Corners)

  内侧线提前转向，外侧线延迟转向，使转角点交错分布：

  正确的交错转角:

      ┌─────────────●━━━━━━━━  Line 0 (最外侧，最晚转)
      │        ┌────●━━━━━━━━  Line 1
      │   ┌────┘
      │   │  ┌─●━━━━━━━━━━━━━  Line 2 (最内侧，最早转)
      │   │  │
      ●───●──●
     L0   L1  L2

  间距在整个路径上保持一致

  实现算法：

  // 计算交错转角的偏移量
  VECTOR2I CalculateCornerOffset(int lineIndex, int totalLines,
                                  int spacing, const DIRECTION_45& turnDir) {
      // 距离中心线的偏移
      int centerOffset = (lineIndex - (totalLines - 1) / 2.0) * spacing;
      
      // 转角方向决定偏移方向
      VECTOR2I offset;
      if (turnDir.IsObtuse()) {
          // 钝角转弯：内侧线需要提前转
          offset = turnDir.Left().ToVector() * centerOffset;
      } else {
          // 锐角转弯：外侧线需要延迟转
          offset = turnDir.Right().ToVector() * centerOffset;
      }
      return offset;
  }

  方案 B: 弧形转角法 (Arc Corners) - 进阶实现

  使用圆弧代替直角，所有线共享同心圆弧：

  弧形转角（进阶）:

          ╭────────━━━━━━━━  Line 0 (R = R_base + 2*spacing)
         ╭┴───────━━━━━━━━━  Line 1 (R = R_base + spacing)
        ╭┴────────━━━━━━━━━  Line 2 (R = R_base)
        │
        │

  此方案保证转角处间距精确一致，但需要 KiCad 的圆弧走线支持（已具备）。

  ---
  难点 2: 障碍物协同避让 (Coordinated Obstacle Avoidance)

  问题描述

  当其中一条线遇到障碍物时，如何处理整个线组的行为？几种可能的情况：

  场景1: 单一障碍阻挡部分线

      ━━━━━━━━━━━━━━  Line 0 ──────→ 无障碍
      ━━━━━━━▓▓▓━━━━  Line 1 ──────→ 被阻挡
      ━━━━━━━━━━━━━━  Line 2 ──────→ 无障碍
             ↑
           障碍物

  场景2: 宽障碍阻挡整组

      ━━━━━━━▓▓▓━━━━  Line 0 ─┐
      ━━━━━━━▓▓▓━━━━  Line 1 ─┼──→ 全部被阻挡
      ━━━━━━━▓▓▓━━━━  Line 2 ─┘

  场景3: 障碍物在线组中间

      ━━━━━━━━━━━━━━  Line 0
      ━━━━▓▓▓━━━━━━━  Line 1  ← 障碍物仅在中间
      ━━━━━━━━━━━━━━  Line 2

  解决方案

  策略矩阵：
  ┌─────────────┬──────────────────────────────────────┬──────────────────┐
  │    模式     │                 行为                 │     适用场景     │
  ├─────────────┼──────────────────────────────────────┼──────────────────┤
  │ STRICT      │ 任一线被阻挡则整组停止               │ 高一致性要求场景 │
  ├─────────────┼──────────────────────────────────────┼──────────────────┤
  │ WALKAROUND  │ 整组一起绕行                         │ 默认模式         │
  ├─────────────┼──────────────────────────────────────┼──────────────────┤
  │ SPLIT_MERGE │ 被阻挡的线临时分离绕行，之后重新合并 │ 复杂障碍场景     │
  ├─────────────┼──────────────────────────────────────┼──────────────────┤
  │ PUSH_SHOVE  │ 推开可移动的障碍物                   │ 激进布线模式     │
  └─────────────┴──────────────────────────────────────┴──────────────────┘
  核心算法 - 统一障碍检测：

  struct ObstacleCheckResult {
      bool anyBlocked;           // 是否有任何线被阻挡
      bool allBlocked;           // 是否所有线都被阻挡
      int  blockedCount;         // 被阻挡的线数量
      std::vector<int> blockedLines;  // 被阻挡的线索引
      SHAPE_LINE_CHAIN suggestedDetour;  // 建议的绕行路径
  };

  ObstacleCheckResult CheckGroupObstacles(
      const std::vector<LINE>& lines,
      const VECTOR2I& newPoint,
      NODE* world) 
  {
      ObstacleCheckResult result = {};

      // 1. 计算线组的包围盒（Fat Trace 方法）
      BOX2I groupBounds = ComputeGroupBounds(lines, newPoint);
    
      // 2. 在包围盒范围内查询障碍物
      std::vector<OBSTACLE> obstacles;
      world->QueryColliding(groupBounds, obstacles);

      if (obstacles.empty()) {
          return result;  // 无障碍
      }
      
      // 3. 逐线精确检测
      for (int i = 0; i < lines.size(); i++) {
          SHAPE_LINE_CHAIN tentative = lines[i].CLine();
          tentative.Append(ComputeFollowerPoint(lines, i, newPoint));
          
          if (world->CheckColliding(&tentative)) {
              result.blockedLines.push_back(i);
          }
      }

      result.blockedCount = result.blockedLines.size();
      result.anyBlocked = (result.blockedCount > 0);
      result.allBlocked = (result.blockedCount == lines.size());

      // 4. 如果需要，计算绕行路径
      if (result.anyBlocked && m_mode == WALKAROUND) {
          result.suggestedDetour = ComputeGroupWalkaround(groupBounds,
  obstacles);
      }
      
      return result;
  }

  WALKAROUND 绕行算法：

  SHAPE_LINE_CHAIN ComputeGroupWalkaround(
      const BOX2I& groupBounds,
      const std::vector<OBSTACLE>& obstacles) 
  {
      // 将整组视为一个"胖走线"进行 Walkaround
      int fatWidth = groupBounds.GetWidth();
      
      // 使用现有的 WALKAROUND 算法，但使用扩展的间隙
      WALKAROUND walkaround(m_world, m_router);
      
      // 创建一个虚拟的胖线段
      LINE fatLine;
      fatLine.SetWidth(fatWidth);
      fatLine.SetShape(/* leader 路径 */);

      // 计算绕行
      LINE result;
      walkaround.Route(fatLine, result);

      return result.CLine();  // 返回 leader 的新路径
  }

  难点 3: 动态间距计算与规则遵守 (Dynamic Spacing & Rule Compliance)

  问题描述

  1. 不同网络可能有不同的间距规则：Net_A 到 Net_B 可能需要 0.2mm，Net_B 到 Net_C
   可能需要 0.3mm
  2. 不同层可能有不同的间距要求：顶层 0.15mm，内层 0.2mm
  3. 换层时的间距重新计算：过孔直径不同于走线宽度

  解决方案

  间距矩阵计算：

  class MULTI_LINE_SPACING {
  public:
      // 初始化时计算完整的间距矩阵
      void Initialize(const std::vector<NET_HANDLE>& nets, 
                      int layer,
                      BOARD_DESIGN_SETTINGS& bds) 
      {
          int n = nets.size();
          m_spacingMatrix.resize(n, std::vector<int>(n, 0));
          
          for (int i = 0; i < n; i++) {
              for (int j = i + 1; j < n; j++) {
                  // 查询设计规则获取网络间间距
                  int spacing = bds.GetNetClassClearance(
                      nets[i], nets[j], layer);
                  
                  // 加上走线宽度的一半
                  int traceWidth_i = bds.GetNetClassTraceWidth(nets[i], layer);
                  int traceWidth_j = bds.GetNetClassTraceWidth(nets[j], layer);
                  
                  int centerSpacing = spacing + (traceWidth_i + traceWidth_j) / 
  2;
          
                  m_spacingMatrix[i][j] = centerSpacing;
                  m_spacingMatrix[j][i] = centerSpacing;
              }
          }

          // 计算累积偏移
          ComputeCumulativeOffsets();
      }

      // 获取第 i 条线相对于 leader 的偏移量
      int GetOffset(int lineIndex) const {
          return m_cumulativeOffsets[lineIndex];
      }

  private:
      void ComputeCumulativeOffsets() {
          m_cumulativeOffsets.resize(m_spacingMatrix.size());
          m_cumulativeOffsets[0] = 0;  // Leader 无偏移
          
          for (int i = 1; i < m_spacingMatrix.size(); i++) {
              // 偏移 = 前一条线偏移 + 与前一条线的间距
              m_cumulativeOffsets[i] = m_cumulativeOffsets[i-1] 
                                      + m_spacingMatrix[i-1][i];
          }
          
          // 调整使线组以 leader 为中心
          int totalWidth = m_cumulativeOffsets.back();
          int centerOffset = totalWidth / 2;
          for (auto& offset : m_cumulativeOffsets) {
              offset -= centerOffset;
          }
      }
      
      std::vector<std::vector<int>> m_spacingMatrix;
      std::vector<int> m_cumulativeOffsets;
  };

  换层处理：

  void OnLayerChange(int newLayer) {
      // 重新计算新层的间距
      m_spacing.Initialize(m_nets, newLayer, m_board->GetDesignSettings());
      
      // 重新计算所有 follower 的偏移
      for (int i = 0; i < m_lines.size(); i++) {
          m_lines[i].m_offset = m_spacing.GetOffset(i);
      }

      // 过孔位置也需要根据新间距调整
      AdjustViaPositions();
  }

  难点 4: 线序确定与优化 (Line Ordering)

  问题描述

  用户选择 N
  个起点时，如何确定哪条线在左侧、哪条在右侧？错误的排序可能导致交叉：

  错误排序导致交叉:

    Src Pads:  A  B  C  D        Dst Pads:  D  C  B  A
               ●  ●  ●  ●                    ●  ●  ●  ●
               │  │  │  │                    │  │  │  │
               │  ╲│╱ │  │                    │  │  │  │
               │  ╱│╲ │  │   ← 交叉！         │  │  │  │
               │  │  │  │                    │  │  │  │

  解决方案

  方案 A: 几何排序

  根据起点相对于布线方向的垂直投影排序：

  void SortLinesByGeometry(std::vector<MDRAG_LINE>& lines,
                            const VECTOR2I& routeDirection)
  {
      // 计算垂直于布线方向的轴
      VECTOR2I perpAxis(-routeDirection.y, routeDirection.x);

      std::sort(lines.begin(), lines.end(), 
          [&perpAxis](const MDRAG_LINE& a, const MDRAG_LINE& b) {
              // 投影到垂直轴上
              int projA = a.startPoint.Dot(perpAxis);
              int projB = b.startPoint.Dot(perpAxis);
              return projA < projB;
          });
  }

  方案 B: 拓扑排序（基于目标）

  如果已知目标点，根据目标点位置反向推导最优排序：

  void SortLinesByDestination(std::vector<MDRAG_LINE>& lines,
                               const std::vector<VECTOR2I>& destinations) 
  {
      // 使用匈牙利算法或贪心匹配找到最少交叉的配对
      std::vector<std::pair<int, int>> matching = 
          MinimizeCrossings(lines, destinations);
      
      // 根据匹配结果重新排序
      ReorderByMatching(lines, matching);
  }

  方案 C: 用户手动调整

  提供快捷键让用户在布线过程中交换线序：

  // 快捷键 'O' - 线序优化
  // 快捷键 'Shift+O' - 反转线序
  void OnKeyPress(int key) {
      if (key == 'O') {
          OptimizeLineOrder();
      } else if (key == 'O' + SHIFT) {
          ReverseLineOrder();
      }
  }

  难点 5: 实时性能优化 (Real-time Performance)

  问题描述

  每次鼠标移动事件（约 60Hz）都需要：
  1. 计算 N 条线的新路径段
  2. 对每条线进行碰撞检测
  3. 可能触发 Push-and-Shove 计算
  4. 更新图形预览

  当 N = 16（16-bit 总线）时，计算量是单线的 16 倍。

  解决方案

  优化策略 1: 增量计算

  只计算变化的部分，复用不变的部分：

  bool Move(const VECTOR2I& aP, ITEM* aEndItem) {
      // 快速检查：如果鼠标移动很小，跳过计算
      if ((aP - m_lastMousePos).EuclideanNorm() < MOVE_THRESHOLD) {
          return true;
      }

      // 只重新计算最后一段
      SEGMENT newLeaderSeg = ComputeNewSegment(m_leader, aP);

      // 检查是否需要转向
      if (!NeedsTurn(newLeaderSeg, m_lastLeaderSeg)) {
          // 只更新最后一段的终点，不创建新段
          for (auto& line : m_lines) {
              line.UpdateLastSegmentEndpoint(/* computed */);
          }
      } else {
          // 需要转向，创建新段
          for (auto& line : m_lines) {
              line.AppendSegment(/* computed */);
          }
      }
      
      m_lastMousePos = aP;
  }

  优化策略 2: 空间索引预过滤

  使用 R-tree 快速排除不可能碰撞的区域：

  class GroupCollisionChecker {
  public:
      void PrecomputeNearbyObstacles(const BOX2I& groupBounds) {
          // 只在边界变化显著时重新查询
          if (!m_cachedBounds.Contains(groupBounds)) {
              BOX2I expandedBounds = groupBounds;
              expandedBounds.Inflate(CACHE_MARGIN);  // 预留缓冲

              m_nearbyObstacles.clear();
              m_world->QueryInArea(expandedBounds, m_nearbyObstacles);
              m_cachedBounds = expandedBounds;
          }
      }
      
      bool QuickCheck(const SEGMENT& seg) {
          // 先用缓存的障碍物做快速检查
          for (const auto& obs : m_nearbyObstacles) {
              if (seg.Collide(obs)) return true;
          }
          return false;
      }

  private:
      BOX2I m_cachedBounds;
      std::vector<ITEM*> m_nearbyObstacles;
  };

  优化策略 3: 延迟精确计算

  粗略预览 + 精确验证分离：

  void UpdatePreview(const VECTOR2I& aP) {
      // 快速计算：简化碰撞检测，只用边界框
      auto quickPaths = ComputeQuickPaths(aP);
      
      // 立即显示预览（可能不完全准确）
      DisplayPreview(quickPaths);

      // 异步进行精确计算
      m_preciseCalcPending = true;
  }

  void OnIdle() {
      if (m_preciseCalcPending) {
          // 精确计算并更新
          auto precisePaths = ComputePrecisePaths(m_lastMousePos);
          if (precisePaths != m_displayedPaths) {
              DisplayPreview(precisePaths);
          }
          m_preciseCalcPending = false;
      }
  }

  优化策略 4: 并行计算（进阶）

  对于大量线（N > 8），使用并行计算：

  #include <execution>

  void ComputeAllFollowerPaths(const SEGMENT& leaderSeg) {
      std::for_each(std::execution::par_unseq,
          m_lines.begin(), m_lines.end(),
          [&](LINE& line) {
              line.ComputeOffsetPath(leaderSeg, line.m_offset);
          });
  }

  难点 6: 过孔放置策略 (Via Placement Strategy)

  问题描述

  用户按 'V' 换层时，需要为所有 N 条线放置过孔：
  1. 过孔直径可能大于走线间距，导致重叠
  2. 不同网络可能需要不同规格的过孔
  3. 过孔需要满足 via-to-via 间距规则

  问题示例 - 过孔重叠:

  走线间距 0.15mm，过孔直径 0.4mm

      ━━━━━⊙━━━━━  Line 0
      ━━━━━⊙━━━━━  Line 1  ← 过孔重叠！
      ━━━━━⊙━━━━━  Line 2

  解决方案

  方案 A: 过孔错位排列 (Staggered Vias)

  错位排列避免重叠:

      ━━━━━━━⊙━━━━━━━  Line 0
      ━━━━⊙━━━━━━━━━━  Line 1  (提前放置)
      ━━━━━━━━━━⊙━━━  Line 2  (延后放置)

  std::vector<VECTOR2I> ComputeStaggeredViaPositions(
      const VECTOR2I& userClickPos,
      const std::vector<LINE>& lines)
  {
      std::vector<VECTOR2I> viaPositions;

      // 计算过孔间最小间距
      int viaToViaSpacing = m_board->GetDesignSettings().GetViaToClearance();
      int viaDiameter = GetViaDiameter();
      int requiredSpacing = viaDiameter + viaToViaSpacing;
      
      // 计算走线方向
      VECTOR2I dir = GetRouteDirection();

      for (int i = 0; i < lines.size(); i++) {
          // 沿走线方向错开
          int stagger = i * requiredSpacing;
          VECTOR2I viaPos = GetLinePoint(lines[i], userClickPos) + dir * 
  stagger;
          viaPositions.push_back(viaPos);
      }

      return viaPositions;
  }

  方案 B: 扇出式过孔 (Fanout Vias)

  扇出式排列:

             ⊙ Line 0
            ╱
      ━━━━━╳━━━━━━  (汇合点)
            ╲
             ⊙ Line 2

  过孔在扇出位置放置，然后汇合继续平行布线
