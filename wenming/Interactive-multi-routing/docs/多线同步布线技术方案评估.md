# 多线同步布线技术方案评估

# 1. 实现目的

## 1.1 项目背景

实现PCB设计工具中的多线同步布线功能，支持多条走线保持恒定间距约束的交互式布线。

## 1.2 评估目标

评估5种技术方案的可行性、工时成本和技术难度，选出最适合当前系统集成的实现路径。

## 1.3 最终结论

推荐采用Leader-Follower方案，该方案实现难度适中（难度等级3），工时可控（12人天），且易于集成现有布线引擎。

## 2.2 优缺点对比

### 2.2.1 方案1: Leader-Follower主从跟随（推荐）

**方案概述：**

先对主导线进行完整布线，然后基于几何偏移算法生成跟随线，在每个线段和转角处保持恒定间距。

**技术特点：**

- 采用两阶段布线策略，主导线使用成熟的单线布线引擎
- 跟随线生成采用平行偏移算法，支持直线段、圆弧和斜接三种转角模式
- 障碍物检测采用局部修正策略，仅在冲突区域调整路径
- 失败回退机制支持重新选择主导线或调整间距参数

**优势：**

- 实现复杂度低，可复用现有布线核心算法
- 转角处理技术成熟，圆弧和斜接算法已有参考实现
- 性能优秀，主导线规划后跟随线生成为O(n)复杂度
- 调试和维护成本低，两阶段逻辑清晰易于问题定位

**劣势：**

- 在紧密空间中跟随线可能因障碍物而生成失败
- 主导线选择策略影响整体成功率，可能需要多次尝试
- 对非对称布局支持较弱，所有跟随线必须与主导线保持一致的拓扑

**评估：**

推荐使用。该方案难度等级为3（中等），工时估算为12人天（Delta评估12.3人天），主要技术挑战在于转角间距维护和障碍物规避，但功能完整度高，覆盖直线、转角、绕障等核心流程。

**实施路径：**

- 扩展现有布线接口，添加多线模式、间距参数和主导线选择机制
- 实现偏移几何算法库，支持直线平移、圆弧等距和斜接计算
- 集成障碍物检测模块，实现局部路径修正和冲突回退
- 添加失败处理机制，包括主导线重选和参数调整策略
- 性能优化和全场景测试验证

**关键风险：**

- 风险1：紧密空间中跟随线绕障成功率可能低于预期 → 应对：引入提前空间探测机制，在主导线规划时预留足够空间
- 风险2：转角处间距误差累积可能导致精度问题 → 应对：采用高精度几何计算库，在关键点进行误差补偿

**依赖条件：**

- 需要现有布线引擎支持单线路径规划接口
- 需要几何计算库支持向量运算和曲线偏移
- 需要障碍物查询接口提供快速碰撞检测能力

### 2.2.2 方案2: Fat Trace宽走线通道

**方案概述：**

将多条走线等效为单个宽走线，先规划虚拟通道，再在通道内分解为多条等距平行线。

**技术特点：**

- 通道宽度计算公式：W = n×线宽 + (n-1)×间距
- 虚拟通道规划使用宽走线布线算法
- 分解阶段处理通道内障碍物切割问题
- 转角处采用渐变宽度或切角处理

**优势：**

- 空间预留充分，减少跟随线与障碍物的冲突
- 商业工具中有成熟应用案例
- 适合处理大间距多线布线场景

**劣势：**

- 分解算法复杂，需处理通道内障碍物切割情况
- 转角处几何复杂度高，渐变区域计算困难
- 虚拟通道与实际走线的映射关系需额外维护

**评估：**

不推荐使用。该方案难度等级为4（较难），工时估算为18人天（Delta评估18.0人天），虽然空间预留策略有优势，但分解算法的复杂性和转角处理的困难导致开发成本过高。

### 2.2.3 方案3: Concurrent Planning并发规划

**方案概述：**

基于多智能体路径规划理论，使用冲突优先级搜索算法（CBS/EECBS）同时规划所有走线路径。

**技术特点：**

- 采用多智能体路径规划算法框架
- 冲突检测树构建和优先级分支搜索
- 支持动态约束添加和冲突解决
- 理论完备性保证，可处理复杂拓扑

**优势：**

- 理论完备性强，能找到最优解（如果存在）
- 适合复杂拓扑场景，支持3条以上走线的同步规划
- 可扩展性好，支持自定义约束条件

**劣势：**

- 实现难度极高，需引入全新的算法框架
- 性能开销大，搜索空间随走线数量指数增长
- 不适合实时交互场景，规划时间可能超过秒级
- 与现有系统集成困难，需大量适配工作

**评估：**

不推荐使用。该方案难度等级为5（极难），工时估算为20人天（Delta评估20.0人天），虽然理论上最优，但实现成本过高，且实时性能无法满足交互式布线需求。

### 2.2.4 方案4: Gateway锚点匹配

**方案概述：**

在走线路径的关键位置（拐点、狭窄区域入口）设置锚点，确保所有走线同步通过这些锚点。

**技术特点：**

- 自动识别关键位置并生成锚点
- 锚点间距约束传播机制
- 分段规划，锚点间独立布线
- 支持锚点动态调整和优化

**优势：**

- 适合长距离走线，通过锚点控制全局一致性
- 可控性强，人工可干预锚点位置
- 分段规划降低单次规划复杂度

**劣势：**

- 锚点生成算法复杂，需要拓扑分析和空间判断
- 局部失败需要全局重规划，回退成本高
- 锚点密度难以平衡，过少导致偏移累积，过多影响性能

**评估：**

不推荐使用。该方案难度等级为4（较难），工时估算为18人天（Delta评估18.2人天），锚点生成的复杂性和全局重规划的成本使其不如Leader-Follower方案。

### 2.2.5 方案5: Sequential回溯布线

**方案概述：**

按顺序依次布线每条走线，当后续走线失败时回溯并调整前序走线的路径。

**技术特点：**

- 顺序布线策略，每次布线一条走线
- 失败触发回溯，调整前序走线路径
- 间距约束检查在每次布线后进行
- 回溯深度可配置，避免无限循环

**优势：**

- 实现简单，复用现有单线布线逻辑
- 无需新算法，开发成本低
- 调试容易，逻辑直观

**劣势：**

- 回溯次数不可控，最坏情况下复杂度指数级
- 性能差，可能陷入反复回溯的死循环
- 无法保证找到解，即使解存在也可能超时
- 用户体验差，布线过程不可预测

**评估：**

不推荐使用。该方案难度等级为3（中等），工时估算为16人天（Delta评估17.0人天），虽然实现简单，但性能和可靠性问题严重，不适合生产环境。

# 3. 本项目的难点和疑问点

## 3.1 转角间距维护

**问题描述**

直线段保持固定间距比较简单，但转角处的间距维护是关键挑战：

- 转角几何：内侧线和外侧线的转角半径不同，简单偏移会导致间距变化
- 路径灵活：各条线可以有不同的路径，不要求拓扑一致
- 实时计算：每次鼠标移动都需重新计算路径，确保间距不违规

**解决方案**

**方案A：斜接转角（第一阶段实现）**

沿着两条线段的角平分线方向进行间距偏移，形成尖角连接。内侧线和外侧线按相同的角进行偏移，通过几何计算确保转角处间距保持一致。优点是计算简单、精确，缺点是在锐转角时可能产生较长的尖角。

**方案B：弧形转角（第一阶段实现）**

使用圆弧代替直角，各线采用不同半径的同心圆弧。转角处间距天然保持一致，且走线更平滑。需要现有系统的圆弧走线支持。

**方案C：独立路径（后续扩展）**

允许各线独立选择路径，只保持与相邻线的间距约束。最灵活，但计算复杂度高。

## 3.2 障碍物协同避让

**问题描述**

当某条线遇到障碍物时，如何处理整个线组的行为？

- 场景1（边缘阻挡）：障碍物位于线组一侧，仅阻挡边缘部分线，其余线可沿原路径直行
- 场景2（全组阻挡）：宽障碍物覆盖整个线组宽度，所有线均需绕行
- 场景3（中间分裂）：障碍物位于线组中间，将线组分为两组分别向两侧绕行后汇合

**解决方案**

**策略1：STRICT模式（第一阶段实现）**

任一线被阻挡则整组停止，用户需手动处理。适用于要求严格平行的场景。

**策略2：WALKAROUND模式（第一阶段实现，默认）**

整组一起绕行。将整组视为一个胖走线计算绕行路径。如果组内任何线被阻挡且无法在规则内绕行，整组停止并显示阻塞指示器。简单高效，适合大多数场景。

**策略3：PUSH_SHOVE模式（第一阶段实现）**

推开可移动的障碍物（如其他走线）。使用约束求解器或传播机制，传播推力移动相邻走线直到创建无碰撞空间。伪代码逻辑：while collision: attempt small displacement of obstacle; if obstacle can't move (fixed or board edge), try bending our trace around (hug); if no solution, report blockage。适用于激进布线。

**策略4：HIGHLIGHT_ONLY模式（第一阶段实现）**

忽略障碍物继续布线，仅高亮显示与走线冲突的障碍物。用户可在布线完成后手动处理冲突。适用于快速布局规划或障碍物需要后续调整的场景。

**核心约束**

- 任何单独走线不能违反与任何障碍物的间距规则
- 捆绑走线之间不能违反相互间距规则
- 保持组的相对顺序和拓扑结构

## 3.3 动态间距计算与规则遵守

**问题描述**

- 不同网络间的间距规则可能不同：Net_A 到 Net_B 需要 0.2mm，Net_B 到 Net_C 需要 0.3mm
- 走线宽度可能不同：需要计算中心线间距，而非边缘间距

**解决方案（第一阶段实现方案 B）**

**方案 B：统一间距（简易模式）— 第一阶段实现**

用户设定一个统一的间距值，线组中所有相邻线对均使用该值作为中心线间距。布线过程中可通过快捷键或鼠标滚轮实时动态调整该值，所有线的偏移量立即重新计算并刷新。该模式操作直观、响应快，适用于间距规则一致或用户希望快速手动控制间距的场景。统一间距值需不小于设计规则中所有相关网络对的最大间距要求，否则给出违规提示。

**方案 A：间距矩阵（精确模式）— 后续扩展**

初始化时构建间距矩阵：查询当前层的设计规则，获取每对网络间的间距要求，加上各自走线宽度的一半，得到中心线间距。计算累积偏移，使线组整体居中。布线时实时查表，确保每条线与相邻线的间距满足设计规则。适用于不同网络对间距规则差异较大的场景，作为方案 B 的增强版本在后续迭代中实现。

## 3.4 实时性能

交互式布线要求算法响应时间小于100ms，需优化几何计算和碰撞检测性能。

- 增量计算（第一阶段实现）：只计算变化部分，复用不变部分
- 空间索引（第一阶段实现）：使用 R-tree 预过滤，复用 KiCad 已有基础设施
- 延迟精确计算（后续扩展）：快速显示粗略预览，异步进行精确验证
- 并行计算（后续扩展）：对于大量线（N > 8），使用多线程并行计算

# 4. 方案选择

## 4.1 选择标准

- **工时成本：**优先选择工时在20人天以内的方案
- **技术难度：**优先选择难度等级3及以下的方案
- **集成难度：**优先选择可复用现有模块的方案
- **性能表现：**满足实时交互要求（<100ms响应）
- **维护成本：**代码逻辑清晰，易于后续扩展

## 4.2 推荐方案

**Leader-Follower主从跟随方案**是最优选择，理由如下：

- 工时合理（12人天），在所有可行方案中最低
- 难度适中（等级3），技术风险可控
- 易于集成，可复用现有布线引擎
- 性能优秀，满足实时交互需求
- 技术路线清晰，两阶段策略易于调试和维护

## 4.3 不推荐方案

- **Fat Trace宽走线通道：**分解算法复杂，工时18人天，性价比低
- **Concurrent Planning并发规划：**工时20人天，难度等级5，实现成本过高且性能不满足实时要求
- **Gateway锚点匹配：**锚点生成算法复杂，工时18人天，全局重规划成本高
- **Sequential回溯布线：**性能和可靠性问题严重，虽然工时较低但不适合生产环境

# 7. 架构图和实施步骤要点（Leader-Follower方案）

## 7.1 算法总体流程

输入: 起点集合、终点集合、间距参数

↓

步骤1: 选择主导线(默认选择中间线或用户指定)

↓

步骤2: 使用现有布线引擎规划主导线路径

↓

步骤3: 对每个跟随线执行偏移算法

├─ 直线段: 计算垂直偏移向量

├─ 圆弧转角: 计算等距圆弧

└─ 斜接转角: 计算斜接点坐标

↓

步骤4: 障碍物检测和局部修正

├─ 检测跟随线与障碍物碰撞

├─ 局部路径调整(微调或绕行)

└─ 失败则标记该跟随线

↓

步骤5: 失败处理

├─ 如有跟随线失败,尝试重选主导线

├─ 或调整间距参数

└─ 或提示用户手动干预

↓

输出: 多条等距走线路径

## 7.2 关键实现要点

**偏移几何算法：**

- 直线段：使用垂直单位向量乘以间距进行平移
- 圆弧转角：保持圆心不变，半径增加/减少间距值
- 斜接转角：计算角平分线方向，按间距投影

**障碍物处理：**

- 使用快速碰撞检测算法（AABB包围盒预检测）
- 局部修正优先，仅在冲突区域调整路径
- 绕行策略：保持与主导线的拓扑一致性

**失败回退：**

- 第一级回退：重新选择主导线（尝试外侧线）
- 第二级回退：减小间距参数（在允许范围内）
- 第三级回退：提示用户调整起点/终点位置

## 7.3 性能优化策略

- 几何计算使用向量化指令加速（第一阶段实现）
- 障碍物查询使用空间索引（R-tree或网格）（第一阶段实现）
- 跟随线生成采用并行化处理（后续扩展）
- 缓存主导线的几何信息避免重复计算（第一阶段实现）

# 8. 测试

## 8.1 测试场景

**场景1：直线段测试**

- 2-5条走线的直线平行布线，验证间距保持精度

**场景2：转角测试**

- 90度、45度、任意角度转角，验证圆弧和斜接两种模式的间距保持

**场景3：障碍物绕行测试**

- 跟随线路径上存在障碍物，验证局部修正和绕行策略

**场景4：紧密空间测试**

- 空间不足导致跟随线失败，验证回退机制和用户提示

**场景5：复杂拓扑测试**

- 多个转角、多个障碍物组合，验证整体成功率和性能
