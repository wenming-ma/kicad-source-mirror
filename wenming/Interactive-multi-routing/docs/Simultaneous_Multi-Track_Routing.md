# Simultaneous Multi-Track PCB Routing: Research & Resources

## 1\. Academic Research on Parallel/Bus Routing (2015–2025)

**Concurrent Bus Routing Algorithms:** Recent literature addresses the problem of routing multiple PCB nets (buses) simultaneously with constraints. For example, *Chen-Hao Hsu et al.* propose a **DAG-based algorithm for obstacle-aware topology-matching on-track bus routing**[baloneymath.github.io](https://baloneymath.github.io/files/DAC19_bus.pdf#:~:text=2.3%20Topology,of%20a%20bit%20should%20be). This method ensures all traces in a bus share the same routing topology (same layer transitions, segment count, ordering, etc.), which is crucial for high-speed signals[baloneymath.github.io](https://baloneymath.github.io/files/DAC19_bus.pdf#:~:text=To%20meet%20the%20topology,wires%20of%20a%20bit%20should)[baloneymath.github.io](https://baloneymath.github.io/files/DAC19_bus.pdf#:~:text=of%20three%202,occur%20when%20a%20bit%20has). Similarly, *He-Teng Zhang et al.* introduce a **SAT-based on-track bus routing** approach (IEEE TCAD 2021) that formulates bus routing as a satisfiability problem to concurrently route all bits of a bus under length-matching and design-rule constraints (DOI: 10.1109/TCAD.2020.3044950). *Sheng-Ta Lin et al.* present **MARCH (Maze Routing under a Concurrent and Hierarchical scheme)**, which routes all bits of a bus *concurrently* instead of one-by-one[chengengjie.github.io](https://chengengjie.github.io/papers/C11-DAC19-MARCH.pdf#:~:text=MARCH%20which%20can%20efficiently%20solve,Such%20concurrency). MARCH uses a hierarchical two-stage approach (path planning + track assignment) to optimize total wirelength, segment count, and bus compactness while maintaining fixed spacing and identical topologies across the bundle[chengengjie.github.io](https://chengengjie.github.io/papers/C11-DAC19-MARCH.pdf#:~:text=with%20other%20objectives%20%28e,and%20reroute%20scheme%20to%20further)[chengengjie.github.io](https://chengengjie.github.io/papers/C11-DAC19-MARCH.pdf#:~:text=The%20total%20cost%20Ctot%20al,%28a%29%20All). Another notable work is *Jin-Tai Yan (2022)*, **“Single-Layer Obstacle-Aware Multiple-Bus Routing Considering Simultaneous Escape Length,”** which focuses on routing several buses at once on a dense board while equalizing their escape lengths (to aid length matching across connectors)[nature.com](https://www.nature.com/articles/s41598-026-36925-0?error=cookies_not_supported&code=ea94bd2f-7dea-4285-a988-7dc2c9a6559e#:~:text=7.%20Yan%2C%20J.,12%2C%20902%E2%80%93915%20%282022). These papers often fall under **length-matching** and **topology-matching** routing research, ensuring that parallel signals (e.g. address/data lines) are routed with equal lengths and consistent structures for timing integrity[baloneymath.github.io](https://baloneymath.github.io/files/DAC19_bus.pdf#:~:text=To%20meet%20the%20topology,be%20in%20the%20same%20layer)[baloneymath.github.io](https://baloneymath.github.io/files/DAC19_bus.pdf#:~:text=of%20three%202,occur%20when%20a%20bit%20has). Many are published in IEEE Trans. CAD or presented at DAC/ASPDAC in the last decade, reflecting a growing academic interest in multi-net interactive routing problems. (For instance, see DOI: 10.1109/TCAD.2020.3002546 for Hsu *et al.*, and DOI: 10.1109/TCAD.2020.3044950 for Zhang *et al.*; also arXiv:1810.04805 for a preprint by Hsu *et al.*.) In summary, **academic research confirms that concurrently routing N>2 nets with spacing and timing constraints is an active area**, often termed *bus routing* or *bundle routing*, closely related to high-speed topology and length matching.

## 2\. Open-Source Implementations and Projects

**KiCad and Community Plugins:** As of 2021, KiCad’s built-in interactive router did **not** support simultaneous multi-track routing. Users discussed this on the KiCad forum, noting *“current plugin API doesn’t support such interactive actions”* for parallel trace routing[forum.kicad.info](https://forum.kicad.info/t/plugin-for-routing-parallel-tracks/28831#:~:text=qu1ck%20%20April%2016%2C%202021%2C,6%3A52pm%20%204). Thus, KiCad users resort to workarounds (copying one routed track into an array, then using push-and-shove to pack them)[forum.kicad.info](https://forum.kicad.info/t/plugin-for-routing-parallel-tracks/28831#:~:text=Hi%2C)[forum.kicad.info](https://forum.kicad.info/t/plugin-for-routing-parallel-tracks/28831#:~:text=paulvdh%20%20April%2017%2C%202021%2C,3%3A20am%20%208). A feature request for “multiple parallel traces routing” exists, but native support is still lacking (KiCad issue #1783335). On the other hand, **Freerouting** is an open-source autorouter (originally from Alfons Wirtz, now on GitHub) that can route many nets automatically (batch mode). While Freerouting is not interactive, it demonstrates multi-net routing by exploring topological paths for all selected connections (it imports Specctra DSN files and routes all nets or specified net classes)[github.com](https://github.com/freerouting/freerouting#:~:text=Freerouting)[github.com](https://github.com/freerouting/freerouting#:~:text=Freerouting%20is%20a%20powerful%20PCB,Specctra%20session%20files). *Freerouting’s repository:* [github.com](https://github.com/freerouting/freerouting#:~:text=Freerouting) (GitHub link: `github.com/freerouting/freerouting`). Another project is **OrthoRoute** (by Benchoff, 2023), a GPU-accelerated autorouter for KiCad that uses the PathFinder algorithm to route many nets in parallel on a Manhattan grid[github.com](https://github.com/bbenchoff/OrthoRoute#:~:text=The%20algorithm%20used%20for%20this,treated%20as%20a%20shared%20resource)[github.com](https://github.com/bbenchoff/OrthoRoute#:~:text=treats%20the%20PCB%20as%20a,treated%20as%20a%20shared%20resource). OrthoRoute highlights open-source innovation in routing performance (e.g. parallelized maze routing on GPU), although it focuses on autorouting rather than interactive bundling. *OrthoRoute on GitHub:* [github.com](https://github.com/bbenchoff/OrthoRoute#:~:text=OrthoRoute%20,for%20KiCad) (KiCad plugin, GPU-based). There are also research prototypes (often published as academic code) such as **“MARCH”** and others, but these are not released as end-user tools. In summary, **no fully mature open-source interactive bus router** was found; the community acknowledges the need (see forum discussions) and is exploring autorouting and scripting as interim solutions. (Notably, the KiCad project may introduce bus routing in the future, but as of 2025 it remains a wishlist item[forum.kicad.info](https://forum.kicad.info/t/plugin-for-routing-parallel-tracks/28831#:~:text=There%20is%20no%20plugin%20for,array%20feature%20like%20others%20described).)

## 3\. Technical Blogs and Vendor Whitepapers

Major EDA vendors have implemented parallel trace routing in their tools and shared insights through documentation and blogs:

-   **Altium Designer – Interactive Multi-Routing:** Altium’s documentation describes an “Interactive Multi-Routing” mode allowing the user to route a group of nets together with fixed spacing[altium.com](https://www.altium.com/documentation/altium-designer/pcb/routing/interactive-multi?srsltid=AfmBOorMMkH7LuKyRRqKInDIJguTb_NJpVTZ5yoTknImT1s0At_0-gNy#:~:text=When%20routing%20a%20PCB%20it,route%20multiple%20nets%20simultaneously).
