# Multi-Track (Bus) Routing in PCB EDA – Patents & Technical Documentation

## Overview of Multi-Track Simultaneous Routing

“Multi-track” or “bus” routing refers to interactively routing a group of PCB traces in parallel, with consistent spacing and topology. Instead of laying down one trace at a time, the user can route multiple nets together along a common path (e.g. a data or address bus). Modern PCB CAD tools support this via interactive routers that allow the designer to **drag a bundle of traces** with push-and-shove obstacle avoidance and length-matching features. For example, Altium Designer’s *Interactive Multi-Routing* lets you select a set of source pins and then route them collectively along the same path[altium.com](https://www.altium.com/documentation/altium-designer/pcb/routing/interactive-multi?srsltid=AfmBOoq88zLYAEzHybwBoAfbVthQLG1eouB_1F9npdtDr0QDtxna6m-4#:~:text=When%20routing%20a%20PCB%20it,route%20multiple%20nets%20simultaneously). This dramatically speeds up layout of buses and differential pairs compared to single-net routing. Key challenges addressed by these tools include maintaining spacing rules between traces, preserving the relative order/topology of the group, and handling obstacles by pushing or shoving existing traces out of the way in real-time. Below is a summary of notable patents (2010–2025, plus foundational prior art) and technical resources from major EDA vendors on interactive multi-net routing:

## Academic Research Foundations (1990s–2020s)

Academic work in EDA has provided algorithms that many of the above industrial tools build upon:

-   **Bus Routing Algorithms:** Routing a bus (set of parallel nets) with timing matching has been studied since the 1990s. A notable example is the 2006 paper by M. M. Ozdal and Martin D. F. Wong, *“Two-Layer Bus Routing for High-Speed Printed Circuit Boards”*, ACM TODAES, vol. 11, no. 2, 2006. This work addresses the problem of routing a bus structure between components on two layers **such that all nets meet length-matching constraints** (important for high-speed buses)cs.bilkent.edu.tr. The algorithm can adjust the route of individual traces (adding detours like serpentines) to equalize lengths within the group. It ensures the entire bus is routed with minimal layer changes and length deviation. This concept of **constraint-driven bus routing** is reflected in modern tools which allow designers to specify length match tolerance for a group of nets and then assist in routing them together.
    
-   **Obstacle-Aware and Length-Matching Routing:** As board layouts became more complex, researchers tackled how to route buses around obstacles (other components or keep-out areas) while still matching lengths. **Yan & Chen (2011)** proposed an efficient method for *“Obstacle-aware length-matching bus routing”* (ISPD 2011) that finds initial routes for a bus and then inserts meanders (zigzag detours) as needed to meet a specified length target for each trace[arxiv.org](https://arxiv.org/html/2407.19195v1#:~:text=,Symposium%20on%20Physical%20Design%2C%20ser). They introduce a graph-based algorithm that can handle obstacles and ensures no net in the bus is shorter than a required length (or all nets are matched to the longest). The patent literature above (e.g., Mentor’s bus routing guidance[patents.justia.com](https://patents.justia.com/patent/20090217230#:~:text=adjacency%20in%20terms%20of%20distance,of%20source%20pins%20and%20a)) echoes this by first routing the group as a whole, then tuning individual nets. Recent research (e.g. Wang et al., *ACM TODAES* 2019) has even looked at single-layer bus routing with “detours” to untangle nets without going off a single layer – relevant for dense PCBs where all bus traces must stay on one layer for signal integrity.
    
-   **Interactive Routing & UI:** Early interactive routers (1990s) were often heuristic and manual. A 1998 paper by S. H. Lu et al. introduced an *“interactive routing program with on-line clean-up of sketched routes,”* which foreshadowed today’s sketch-routing: the user would sketch a rough path and the program would clean it up to legal routing in real time. Modern research on human-in-loop EDA continues this thread, optimizing the balance between user control and automation. The interactive push-and-shove behavior seen in KiCad or Altium today owes much to path-finding algorithms (like Lee’s maze routing and its derivatives) combined with computational geometry to slide traces – topics extensively covered in academic literature on interactive placement and routing.
