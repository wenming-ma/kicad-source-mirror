# KiCad多线同步布线技术设计文档

KiCad 多线同步布线技术设计文档

*Multi-Track Simultaneous Routing*

1. 功能概述

1.1 功能定义

多线同步布线是一种交互式 PCB 布线模式，允许用户同时布线 N 条网络（N ≥ 2）。用户选择多个起点后，鼠标移动时所有走线同步生成，自动保持固定间距并尽可能平行。

**本功能专注于单层布线**，不考虑布线过程中的换层和过孔放置。

1.2 目标场景

- 并行数据总线：8-bit/16-bit/32-bit 数据线（D0-D7, A0-A15）
- 地址总线：处理器到存储器的地址线
- 控制信号组：CS, OE, WE 等相关控制信号
- 多对非耦合差分信号

1.3 与现有功能对比

- LINE_PLACER：单条线跟随鼠标，生成新走线
- DIFF_PAIR_PLACER：2条线同步跟随鼠标，固定耦合间距
- MULTI_DRAGGER：拖动已存在的多条走线
- RouteSelected：依次逐条布线，非同步
- MULTI_LINE_PLACER（本功能）：N条线同步布线，固定间距【待实现】

1.4 用户交互流程

**步骤1：选择起点**

用户在 PCB 编辑器中选择多个 Pad/Via（属于不同网络，且在同一层）。例如选择 U1 的 D0-D7 引脚。系统按照焊盘的空间位置自动确定线的排列顺序。

**步骤2：启动多线布线**

通过快捷键或菜单 Route → Interactive Multi-Route 启动。系统根据设计规则自动计算各线间的间距。

**步骤3：交互式布线**

用户移动鼠标，所有走线同步跟随。按 / 或空格切换布线方向，所有走线保持固定间距。各条线可以独立绕开障碍物，不要求路径完全一致。布线过程保持在当前层，不换层。

**步骤4：完成或中断**

点击终点或按 Enter 完成，按 Esc 取消。

2. 核心工程难点

难点1：转角间距维护

**问题描述**

直线段保持固定间距比较简单，但转角处的间距维护是关键挑战：

- 转角几何：内侧线和外侧线的转角半径不同，简单偏移会导致间距变化
- 路径灵活：各条线可以有不同的路径，不要求拓扑一致
- 实时计算：每次鼠标移动都需重新计算路径，确保间距不违规

**转角样式与多线间距维护**

KiCad 在 `DIRECTION_45::CORNER_MODE`（`libs/kimath/include/geometry/direction45.h:66-72`）中定义了转角模式，转角几何由 `BuildInitialTrace()`（`libs/kimath/src/geometry/direction_45.cpp:24-312`）生成。以下 5 种转角样式对应 Altium Designer 的 Corner Style 分类，分别说明各样式下多线同步布线时如何维护线间距。第一阶段优先实现 45 度角、斜切/倒角、圆角三种模式，90 度角和任意角度留作后续扩展。

*1. 45 度角 — `MITERED_45`（第一阶段实现）*

默认模式。走线在两段正交线段之间通过一段 45 度斜线过渡。多线布线时，内侧线的斜线段较短，外侧线的斜线段较长。每条线的转折点沿走线方向的垂直方向偏移，偏移量等于该线到线组中心的累计间距，从而在 45 度过渡区间内保持均匀的线间距。

*2. 90 度角 — `MITERED_90`（后续扩展）*

走线在转角处直接做 90 度直角转弯。多线间距维护方式：每条线的转角顶点沿垂直方向向外偏移，偏移量为该线到线组中心的累计距离。几何关系简单直接——所有线共享相同的转弯方向，每条线的转角点位移量为 `index * spacing`。

*3. 斜切/倒角（Miter/Chamfer）— `MITERED_45` + miter ratio（第一阶段实现）*

将 90 度转角按布线设置中的 miter ratio（斜切比例）进行斜切。多线布线时，斜切比例对所有线统一适用，但由于每条线的转角相对线组中心有不同偏移，实际斜切段的绝对长度各不相同：内侧线斜切段短，外侧线斜切段长，切割长度与该线的垂直偏移量成正比。

*4. 圆角（Rounded/Fillet）— `ROUNDED_45` / `ROUNDED_90`（第一阶段实现）*

转角处用圆弧替代折线。多线布线时，各线形成同心圆弧，半径依次递增：最内侧线半径最小，每条后续线的半径增加一个线间距。由于等间距同心圆弧天然保持恒定距离，间距自动得到维护。约束条件：最小圆弧半径 >= 3 倍线宽，以确保可制造性。

*5. 任意角度（Any Angle）— KiCad `CORNER_MODE` 中尚未实现（后续扩展）*

自由角度布线，走线不受 45 度或 90 度约束。多线布线时，每条线的路径沿参考线路径的局部法线方向做平行偏移。这是最复杂的模式：在锐角处，偏移曲线可能产生自交，需要特殊处理（如裁剪或插入圆弧过渡）。实现该模式需要在 `CORNER_MODE` 枚举中新增值，并在 `BuildInitialTrace()` 中添加对应逻辑。

**通用原则**：所有转角样式下，多线间距的维护方式一致——以参考线（通常为线组中心线或首选网络）的转角几何为基准，其余各线的转角几何沿走线方向的局部法线做垂直偏移。参考线定义基准路径，其他线的转角几何均由此派生。

难点2：障碍物协同避让

**问题描述**

当某条线遇到障碍物时，如何处理整个线组的行为？

- 场景1（边缘阻挡）：障碍物位于线组一侧，仅阻挡边缘部分线，其余线可沿原路径直行
- 场景2（全组阻挡）：宽障碍物覆盖整个线组宽度，所有线均需绕行
- 场景3（中间分裂）：障碍物位于线组中间，将线组分为两组分别向两侧绕行后汇合

**解决方案**

策略1：STRICT 模式（第一阶段实现）- 任一线被阻挡则整组停止，用户需手动处理。适用于要求严格平行的场景。

策略2：WALKAROUND 模式（第一阶段实现，默认）- 被阻挡的线临时分离绕行，绕过障碍后重新汇合恢复间距。未被阻挡的线保持原路径不变。适合大多数场景。

策略3：PUSH_SHOVE 模式（第一阶段实现）- 推开可移动的障碍物（如其他走线）。适用于激进布线。

策略4：HIGHLIGHT_ONLY 模式（第一阶段实现）- 忽略障碍物继续布线，仅高亮显示与走线冲突的障碍物。用户可在布线完成后手动处理冲突。适用于快速布局规划或障碍物需要后续调整的场景。

难点3：动态间距计算与规则遵守

**问题描述**

- 不同网络间的间距规则可能不同：Net_A 到 Net_B 需要 0.2mm，Net_B 到 Net_C 需要 0.3mm
- 走线宽度可能不同：需要计算中心线间距，而非边缘间距

**解决方案（第一阶段实现方案 B）**

*方案 B：统一间距（简易模式）— 第一阶段实现*

用户设定一个统一的间距值，线组中所有相邻线对均使用该值作为中心线间距。布线过程中可通过快捷键或鼠标滚轮实时动态调整该值，所有线的偏移量立即重新计算并刷新。该模式操作直观、响应快，适用于间距规则一致或用户希望快速手动控制间距的场景。统一间距值需不小于设计规则中所有相关网络对的最大间距要求，否则给出违规提示。

*方案 A：间距矩阵（精确模式）— 后续扩展*

初始化时构建间距矩阵：查询当前层的设计规则，获取每对网络间的间距要求，加上各自走线宽度的一半，得到中心线间距。计算累积偏移，使线组整体居中。布线时实时查表，确保每条线与相邻线的间距满足设计规则。适用于不同网络对间距规则差异较大的场景，作为方案 B 的增强版本在后续迭代中实现。

难点4：实时性能优化

**问题描述**

每次鼠标移动（约 60Hz）都需要计算 N 条线的新路径、碰撞检测、可能的 Push-and-Shove、图形预览更新。当 N = 16 时，计算量是单线的 16 倍。

**解决方案**

优化1：增量计算（第一阶段实现）- 只计算变化部分，复用不变部分。鼠标移动很小时跳过计算。

优化2：空间索引（第一阶段实现）- 使用 R-tree 预过滤，只检查可能碰撞的障碍物。KiCad 已有 R-tree 基础设施可直接复用。

优化3：延迟精确计算（后续扩展）- 快速显示粗略预览，异步进行精确验证。

优化4：并行计算（后续扩展）- 对于大量线（N > 8），使用多线程并行计算各线的路径。

3. 整体架构设计

3.1 核心类设计

MULTI_LINE_PLACER 类继承自 PLACEMENT_ALGO，实现多线同步布线功能。该类管理多条线的状态（网络、起点、当前路径、偏移量等），提供线路调整和间距管理接口。

核心接口：

- Start() - 初始化 N 条线的起点
- Move() - 计算各线的新路径段
- FixRoute() - 提交当前路径段
- Traces() - 返回所有线的集合
- AddNet() - 添加待布线网络
- SetMode() - 设置避障模式（WALKAROUND, PUSH_SHOVE, STRICT, HIGHLIGHT_ONLY）

3.2 参考现有代码

- pns_line_placer.cpp - 单线布线核心逻辑
- pns_walkaround.cpp - Walkaround 绕行算法

4. 实现路线图

Phase 1：基础框架（MVP）

目标：实现基本的多线同步布线

- 创建 MULTI_LINE_PLACER 类，实现 PLACEMENT_ALGO 接口
- 从选中的 Pad 创建多线起点，按空间位置排序
- 实现基本的同步跟随：鼠标移动时各线保持固定偏移
- 仅支持直线段，暂不处理转角
- 基础预览显示

验收标准：用户选择多个 Pad，启动多线布线，直线拖动时所有线同步移动并保持间距。

Phase 2：转角处理

目标：正确处理转角间距

- 支持 45°/90° 标准转角
- 实现交错转角算法，内外侧线转角半径不同
- 验证转角处间距不违反设计规则

Phase 3：障碍物处理

目标：完整的障碍物避让

- 实现整组碰撞检测
- 实现 STRICT 模式：任一线被阻挡则整组停止
- 实现 WALKAROUND 模式：被阻挡线分离绕行后汇合
- 实现 PUSH_SHOVE 模式：推开可移动障碍物
- 实现 HIGHLIGHT_ONLY 模式：忽略障碍物，高亮冲突
- 无法通过时显示阻塞提示

Phase 4：优化与完善

目标：性能优化和用户体验

- 增量计算和空间索引优化
- 添加快捷键支持
- Undo/Redo 支持
- 大量线（N > 8）并行计算优化

6. MVP 实现范围说明

MVP 聚焦几何正确性（间距和平行），专注于单层布线。

**MVP 包含：**

- 单层布线：所有走线保持在同一层
- 用户选择 N 条网络启动多线布线
- 鼠标移动时 N 条线同步跟随
- 保持固定间距（来自设计规则）
- 基本障碍物避让（WALKAROUND 模式）
- 45°/90° 角度约束
- 转角间距维护

**MVP 不包含（后续扩展）：**

- 换层和过孔：保持单层布线，不支持布线过程中换层
- 线段长度匹配：不要求各线长度一致
- 信号完整性分析
- 差分对耦合
- 动态间距调整
- 自动网络重排序

这样的 MVP 范围可以快速验证核心功能，专注于单层布线的几何约束问题，后续再根据使用情况扩展多层支持。

7. 风险与缓解

- 性能不足：可能导致卡顿。缓解：渐进式实现，先限制线数（N ≤ 8）
- 边界情况多：可能导致开发周期长。缓解：MVP 优先，复杂场景迭代处理
- 与现有代码耦合：可能引入 bug。缓解：充分复用 DIFF_PAIR_PLACER 模式
- 用户习惯差异：可能不符合预期。缓解：参考 Altium 交互，提供配置选项
